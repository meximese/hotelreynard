## Problem-Solving Guidelines

- Start with the simplest shape that satisfies the requirement.
- Prefer obvious over extensible.
- Make the default solution boring.
- Do not introduce abstraction until duplication or pain is real.
- If a primitive needs explanation, it is probably too complex.
- Optimize for the next user action, not a hypothetical future system.
- When in doubt, cut fields, cut conditions, and cut indirection.
